# whichllm 图形界面

给 [`whichllm`](https://github.com/Andyyyy64/whichllm)（*Find the best LLM that runs on your hardware*）写的桌面图形界面，
用 **Python + Tkinter** 实现，**只依赖标准库**（不需要 PyQt / CustomTkinter 等额外包）。


## 1. 快速开始

```powershell
# 依赖：Python 3.10+（带 tkinter，Windows 官方安装包默认自带）与 whichllm
python -m pip install whichllm

# 启动图形界面
cd whichllm-gui
python run_gui.py
```

Windows 上也可以直接双击：

| 文件 | 说明 |
| --- | --- |
| `启动图形界面.bat` | 用 `pythonw` 启动，不留控制台窗口 |
| `启动图形界面-调试.bat` | 保留控制台，报错更直观 |

如果你用虚拟环境，请用该环境里的解释器运行 `python run_gui.py`；
程序默认通过 `python -m whichllm` 调用同一个解释器下的 whichllm。

## 2. 六个功能页

### 推荐（主页面）
- 顶部一行显示当前生效的硬件（显卡 / 可用显存 / 带宽 / CPU / 内存 / 系统）。
- 左侧筛选面板与 `whichllm` 的命令行选项一一对应：

  | 界面项 | 对应 CLI |
  | --- | --- |
  | 显示数量 | `--top/-n` |
  | 上下文长度 | `--context-length/-c`（支持 `64k`、`128k` 写法） |
  | 量化类型 | `--quant/-q` |
  | 任务侧重 | `--profile`（general / coding / vision / math / any） |
  | 运行适配 | `--fit` / `--gpu-only` |
  | 速度预设、最低速度 | `--speed` / `--min-speed` |
  | 最小参数量 | `--min-params` |
  | 基准证据 | `--evidence` / `--direct` |
  | 仅 CPU 模式 | `--cpu-only` |
  | 模拟 GPU（可多个） | `--gpu`（支持 `2x RTX 4090`） |
  | 显存上限 / 内存带宽 / GPU 序号 | `--vram` / `--bandwidth` / `--gpu-index` |
  | 显存预留 / 内存预算 | `--vram-headroom` / `--ram-budget` |
  | 本地模型库 | `--lm-studio-path` |

- 结果表**点击表头即可排序**，支持关键字过滤（多关键字用空格分隔）。
- 选中任意一行，下方详情面板会给出该模型的完整信息：GGUF 仓库与文件名、显存需求/可用、
  卸载比例、速度区间与置信度、质量分与基准证据来源、下载量、发布日、本地文件路径、风险提示。
- 详情区五个快捷动作：复制模型名、打开 HuggingFace 页面、**去规划**、**生成脚本**、**运行模型**。
- 导出 **JSON / Markdown / CSV**：前两者与 `whichllm --json`、`whichllm --markdown` 输出完全一致
  （直接复用 whichllm 自己的渲染函数，不是另写一套）。

### 硬件
- 显示检测到的每一块 GPU（型号、可用/总显存、带宽、厂商、CUDA/ROCm、是否共享内存）、CPU 与指令集、内存、磁盘、系统。
- 单独一块「当前生效的硬件视图」：把推荐页里的模拟 GPU 与预算设置应用后的结果，方便确认「我到底在按什么硬件排序」。
- 显示 whichllm 版本、运行模式（进程内直连 / 命令行降级）与缓存文件状态。

### 规划
- 输入模型名（支持 HuggingFace 仓库 ID，带 800 条候选自动补全）→ 得到各量化档位需要的显存、
  质量损失，以及一张「哪些显卡能跑、跑多快」的兼容性表格。
- 表格会用颜色标出「能完全装进显存 / 需要部分卸载 / 显存不足」，并对照你自己的可用显存。

### 升级对比
- 添加若干目标显卡（内置 779 个来自 dbgpu 数据库的型号候选，也支持 `2x RTX 5090` 这类写法），
  一键对比「当前硬件 vs 换卡之后」能跑的最佳模型、质量分提升与速度变化。

### 示例脚本
- 为模型生成可直接运行的 Python 示例：有 GGUF 权重用 `llama-cpp-python`，否则用 `transformers`。
- 显示配套的 `uv run --with …` 命令，可复制 / 另存为 `.py` / 直接在新窗口运行。

### 运行
- 交互式对话需要真正的终端，所以这里会在**新的控制台窗口**里启动 `whichllm run`；
  启动前会先把完整命令显示出来（也可复制到别处执行）。

## 3. 它为什么是即时的

`whichllm` 每次运行都要重新检测硬件，本机（RTX 4070 Laptop）实测 **约 7.5 秒**，
如果界面上每改一个筛选条件都重跑一遍命令，体验会很糟。因此本程序：

1. 在**进程内**复用 whichllm 的排序管线（`detect_hardware` / `group_models` / `rank_models` 等）；
2. 把「硬件检测 / 模型列表 / 基准数据」缓存起来，只在需要时重取；
3. 于是首次计算约 7.5 秒，之后每次调整筛选条件只需**重新排序，实测 0.03–0.12 秒**；
4. 所有耗时工作都在后台线程执行，结果通过队列回到 Tk 主线程，界面不会卡死；
   同一通道内后提交的任务会取代先前的任务，避免旧结果覆盖新结果。

如果某个 whichllm 版本改动了内部接口，程序会自动降级为调用
`python -m whichllm --json` 子进程并解析输出（界面右上角会显示当前模式），功能保持可用。

## 4. 目录结构

```
whichllm-gui/
├── run_gui.py                 # 启动脚本
├── 启动图形界面.bat            # 双击启动（无控制台）
├── 启动图形界面-调试.bat        # 双击启动（保留控制台）
├── README.md
└── whichllm_gui/
    ├── __main__.py            # python -m whichllm_gui
    ├── app.py                 # 主窗口：菜单、标题栏、选项卡、状态栏
    ├── engine.py              # 数据层：进程内管线 + 缓存 + 子进程降级 + 格式化
    ├── export.py              # 导出 JSON / Markdown / CSV 与详情文本
    ├── theme.py               # 深色主题、字体、ttk 样式
    ├── widgets.py             # 可排序表格、卡片、滚动容器、候选输入、任务调度
    ├── context.py             # 共享上下文、配置持久化、弹窗
    └── views/
        ├── recommend.py       # 推荐
        ├── hardware.py        # 硬件
        ├── plan.py            # 规划
        ├── upgrade.py         # 升级对比
        ├── snippet.py         # 示例脚本
        └── run.py             # 运行
```

配置文件写在 `%APPDATA%\whichllm-gui\settings.json`（窗口大小、上次的筛选条件），
删除它即可恢复默认。

## 6. 常见问题

**界面打不开、提示没有 tkinter？**
Windows 官方 Python 安装包默认包含 tkinter；Linux 需要单独装（如 `sudo apt install python3-tk`）。

**提示找不到 whichllm？**
先 `python -m pip install whichllm`。注意界面调用的是**运行界面所用的那个 Python** 里的 whichllm；
用虚拟环境时请确保两者一致。

**「重新抓取模型数据」很慢或失败？**
该按钮会用 `--refresh` 绕过缓存重新访问 HuggingFace，需要能正常联网。
日常使用不必点它，缓存有效期内直接点「开始推荐」即可。

**数据和命令行对不上？**
「推荐」页的结果、JSON / Markdown 导出都与 `whichllm` 同源；唯一差别是界面会缓存硬件检测结果，
所以在同一个界面会话里改了硬件配置（比如插拔显卡）后，请点「重新检测硬件」。

**速度/质量后面的 `?`、`~`、`!sr` 是什么？**
沿用 whichllm 的标记：`?` 表示速度估算置信度低，`~` 表示质量分来自推断，`!sr` 表示模型方自报数据。
详情面板里有完整文字说明。

## 7. 说明

- 本程序是 whichllm 的**界面封装**，所有推荐、显存估算、速度预测逻辑都来自 whichllm 本身，
  升级 whichllm 即可获得最新能力；界面本身不联网（联网行为全部发生在 whichllm 内部）。
- 已按 whichllm **0.5.20** 的内部接口实现，并带有子进程降级兜底。
